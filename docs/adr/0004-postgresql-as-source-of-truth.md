# PostgreSQL как источник истины

Перед production-релизом Mini App проект переходит с SQLite на PostgreSQL. PostgreSQL запускается отдельным контейнером в текущем Docker Compose, bot/API остаются единым приложением, а доступ к данным и миграции переходят на SQLAlchemy Async + Alembic. Перенос выполняется в короткое окно остановки записи: после backup и успешных smoke-тестов PostgreSQL становится единственным runtime-хранилищем, а SQLite сохраняется только как архивный backup на период отката.

## Considered Options

- Оставить SQLite: меньше изменений, но хуже подходит для WebSocket, параллельных записей и контроля версий данных.
- Использовать dual-write SQLite + PostgreSQL: снижает риск мгновенного cutover, но создаёт сложную задачу согласования двух источников.
- Перейти на PostgreSQL одним cutover: выбранный вариант; требует окна недоступности и backup, зато оставляет один источник истины.
