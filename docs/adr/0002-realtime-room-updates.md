# Realtime-обновления списка внутри комнаты

Mini App будет доставлять изменения открытой комнаты участникам через realtime-канал, чтобы действие одного пользователя появлялось у остальных без ручного обновления. Событие не считается окончательным состоянием: после получения события клиент должен синхронизировать актуальное состояние через API, а после reconnect выполнить полный refetch; это защищает от пропущенных событий и не переносит бизнес-правила в браузер.

## Consequences

- backend должен проверять членство в комнате при подписке на канал;
- операции покупки и изменения количества должны быть безопасны при повторной доставке;
- при одном экземпляре приложения допустим connection manager в памяти, но горизонтальное масштабирование потребует общего брокера событий или другого межпроцессного транспорта;
- offline-first и долговечная очередь команд в это решение не входят.
